# 초등教원 연수 홈페이지 UI/UX 설계 문서

> 문서 목적: 이 문서는 **디자인 스펙**이며 프로덕션 코드를 포함하지 않는다. 다음 단계(퍼블리싱/구현 담당자)가 이 문서만 보고 페이지 구조·콘텐츠·컴포넌트·톤을 그대로 재현할 수 있도록 작성한다.
>
> 대상 사용자: 코딩 경험이 거의 없는 초등학교 교사. 톤: 쉽고 친근하되, 연수 자료로서 신뢰감을 주어야 함(과하게 유치하지 않음).
>
> 학습 목표 2가지:
> 1. 구글 제미나이(Gemini)를 활용한 "바이브 코딩" 기초 이해
> 2. 구글 스프레드시트 + Apps Script로 교수학습자료 스스로 만들기

---

## 1. 사이트맵 / 정보구조(IA)

```
/                         홈 (랜딩)
/vibe-coding/             바이브 코딩 기초 (제미나이 활용)
  /vibe-coding/what-is/     - 바이브 코딩이 뭔가요?
  /vibe-coding/start-gemini/ - 제미나이로 첫 실습 따라하기
  /vibe-coding/prompt-tips/  - 프롬프트(질문) 잘 쓰는 법
/sheets-appsscript/       구글시트 x 앱스크립트 자료 개발
  /sheets-appsscript/basics/     - 스프레드시트 기초 다지기
  /sheets-appsscript/appsscript-101/ - 앱스크립트 첫걸음
  /sheets-appsscript/recipes/    - 교과별 실전 레시피 (출석부, 자동채점, 시간표 등)
/practice/                실습 / 자료실
  /practice/worksheets/     - 실습용 워크시트(따라 하기 PDF/시트 사본)
  /practice/templates/      - 바로 쓰는 템플릿(시트 사본, 스크립트 코드)
  /practice/gallery/        - 선생님들이 만든 결과물 갤러리
/faq/                      자주 묻는 질문 / 문제 해결
/about/                    연수 소개 (대상, 방법, 문의)
```

### 페이지별 목적 요약

| 페이지 | 목적 | 핵심 사용자 행동 |
|---|---|---|
| 홈 | 연수 전체를 한눈에 소개, 두 학습 트랙으로 안내 | "바이브 코딩 시작하기" 또는 "시트×앱스크립트 시작하기" 클릭 |
| 바이브 코딩 기초 | 코딩 경험 없이도 제미나이로 코드를 "대화하듯" 만드는 개념·실습 | 순서대로 3개 하위 페이지를 따라가며 개념 → 실습 → 응용 |
| 구글시트×앱스크립트 | 실제 학교 업무/수업 자료를 스스로 자동화하는 법 | 기초 → 앱스크립트 첫걸음 → 교과별 레시피 순으로 학습 |
| 실습/자료실 | 손으로 따라 해볼 실습지·템플릿·다른 교사 사례 다운로드 | 템플릿 사본 만들기, 워크시트 다운로드, 갤러리 둘러보기 |
| FAQ | 자주 막히는 지점(권한 오류, 실행 승인 등) 자가 해결 | 검색/아코디언으로 답 찾기 |
| 연수 소개 | 연수 목적, 대상, 문의처 안내 | 신뢰 확보, 문의하기 |

## 2. 헤더 / 푸터 내비게이션 구조

### 헤더 (전 페이지 공통, sticky)

```
[🏫 로고/연수명]   홈   바이브 코딩 기초   시트×앱스크립트   실습/자료실   FAQ   [연수 소개 →]
```

- 좌측: 로고 + 연수명 텍스트 (예: "AI 수업 도구 만들기 연수") — 클릭 시 홈으로 이동
- 중앙/우측: 5개 1차 메뉴 (모바일에서는 햄버거 메뉴로 축소)
- 가장 우측: "연수 소개" 또는 "시작하기" 버튼을 강조 버튼(Primary)으로 배치
- 현재 위치는 메뉴에 밑줄/배경색으로 표시 (active state)
- 모바일: 햄버거 아이콘 → 풀스크린 드로어 메뉴, 각 항목 터치 영역 44px 이상

### 푸터 (전 페이지 공통)

```
[로고]  이 연수에 대하여
        - 연수 소개
        - 자주 묻는 질문
        - 문의하기 (이메일/폼)

        바로가기
        - 바이브 코딩 기초
        - 시트×앱스크립트
        - 실습/자료실

        (선택) 저작권/출처 안내, 최종 업데이트일
```

- 3단 컬럼(모바일에서는 세로 스택)
- 하단에 "이 자료는 교육 목적의 연수 자료입니다" 같은 안내 문구 한 줄
- 다크 배경 대신 밝은 회색 배경 권장(친근한 톤 유지, 초등 교사 대상이므로 과한 다크 UI 지양)

## 3. 페이지별 핵심 섹션 & 레이아웃 (텍스트 placeholder 기반)

> 각 섹션은 "섹션명 → 구성요소 → placeholder 텍스트" 순으로 기술. 실제 카피는 구현 시 다듬되, 어조(친근한 존댓말, ~해봐요/~해볼까요?)는 유지.

### 3.1 홈 (`/`)

**A. 히어로 섹션**
- 레이아웃: 중앙 정렬, 배경에 부드러운 일러스트/아이콘(로봇+연필 등)
- 헤드라인: "코딩 몰라도 괜찮아요, 선생님! AI와 함께 수업 도구를 직접 만들어봐요"
- 서브텍스트: "구글 제미나이와 스프레드시트만 있으면 충분합니다. 지금 시작해볼까요?"
- CTA 버튼 2개(나란히): `[바이브 코딩 시작하기]`(Primary) / `[시트×앱스크립트 시작하기]`(Secondary)

**B. 왜 배워야 할까요 (가치 제안, 3카드)**
- 카드1: "🎯 나만의 수업 도구" — "출석부, 채점기, 퀴즈까지 직접 만들어요"
- 카드2: "🤖 AI가 코드를 대신 써줘요" — "코딩을 몰라도 제미나이에게 말로 설명하면 끝"
- 카드3: "⏱ 반복 업무 시간 절약" — "한 번 만들면 매 학기 재사용 가능해요"

**C. 학습 경로 안내 (2트랙 비교 카드)**
- 좌: "① 바이브 코딩 기초" 카드 — 아이콘, 한 줄 설명, "3단계로 배워요" 배지, `[시작하기]` 버튼
- 우: "② 구글시트×앱스크립트" 카드 — 동일 구조

**D. 어떻게 진행되나요 (스텝 인디케이터, 가로 4단계)**
1. 개념 이해하기 → 2. 따라 해보기 → 3. 나만의 자료 만들기 → 4. 갤러리에 공유하기

**E. 자료실 미리보기 (템플릿 3~4개 카드 그리드)**
- "바로 쓰는 템플릿" 섹션, 각 카드에 썸네일 + 제목 + `[사본 만들기]` 버튼

**F. FAQ 미리보기 (아코디언 3개) + `[FAQ 전체 보기 →]` 링크**

---

### 3.2 바이브 코딩 기초 (`/vibe-coding/`)

**공통 페이지 헤더 배너**
- 좌: 브레드크럼(홈 > 바이브 코딩 기초) / 우: 진행 단계 표시(1/3, 2/3, 3/3)

**A. 개요 섹션** (`/vibe-coding/what-is/`)
- "바이브 코딩이 뭔가요?" — 개념을 비유로 설명하는 인포그래픽 placeholder
- 카피 예시: "바이브 코딩이란, 코드를 직접 타이핑하지 않고 'AI에게 원하는 것을 자연어로 설명해서' 코드를 완성해가는 방식이에요."
- "이런 분께 추천해요" 체크리스트 (코딩 처음, 반복 업무 자동화하고 싶은 교사 등)

**B. 실습 섹션** (`/vibe-coding/start-gemini/`)
- "STEP 컴포넌트"로 구성된 따라하기 가이드 (아래 §5 컴포넌트 참고)
  - Step 1: "제미나이 접속하기" (스크린샷 placeholder + 캡션)
  - Step 2: "원하는 걸 말로 설명해보기" (예시 프롬프트 박스)
  - Step 3: "결과 확인하고 수정 요청하기"
- 각 Step 카드에: 스크린샷 영역(placeholder), 설명 텍스트, "선생님 TIP" 콜아웃(선택)

**C. 프롬프트 팁 섹션** (`/vibe-coding/prompt-tips/`)
- "좋은 질문 vs 아쉬운 질문" 비교 카드(2열, 대비 색상)
- 예시 프롬프트 카드 5~6개 (복사 버튼 포함, 코드/텍스트 블록 컴포넌트 재사용)

**D. 페이지 하단 공통: "다음 단계로" 내비게이션**
- `[← 이전: 개념 이해]` / `[다음: 실습해보기 →]` 페이지네이션 버튼

### 3.3 구글시트×앱스크립트 자료 개발 (`/sheets-appsscript/`)

**A. 개요 섹션** (`/sheets-appsscript/basics/`)
- "스프레드시트, 이 정도만 알면 충분해요" — 함수/시트 기본 개념 카드 4개(셀, 함수, 시트 탭, 공유)
- 스크린샷 placeholder로 화면 구조 설명

**B. 앱스크립트 첫걸음** (`/sheets-appsscript/appsscript-101/`)
- "앱스크립트가 뭔가요?" 설명 + 비유("스프레드시트에 붙이는 자동화 로봇")
- Step 컴포넌트로 "확장 프로그램 > Apps Script 열기 → 코드 붙여넣기 → 실행 → 권한 승인" 순서 안내
- 코드 블록 컴포넌트(복사 버튼 포함)로 예시 스크립트 표시 (placeholder: `// 여기에 예시 코드가 들어갑니다`)
- "권한 승인은 왜 필요한가요?" 안내 콜아웃 (초보자가 겁먹지 않도록 안심시키는 톤)

**C. 교과별 실전 레시피** (`/sheets-appsscript/recipes/`)
- 레시피 카드 그리드 (예: "자동 출석부", "객관식 자동채점기", "모둠 자동 편성기", "시간표 생성기")
- 각 카드: 난이도 배지(쉬움/보통/도전), 소요시간(예: 15분), 썸네일, `[따라하기 →]` 버튼
- 클릭 시 개별 레시피 상세 페이지(Step 컴포넌트 + 코드 블록 + 완성 시트 사본 링크)

---

### 3.4 실습 / 자료실 (`/practice/`)

**A. 탭 내비게이션**: `워크시트` | `템플릿` | `갤러리`

**B. 워크시트 탭**
- 리스트형 카드: 제목, 대상 단계(초급/중급), 다운로드 버튼(PDF), 예상 소요시간

**C. 템플릿 탭**
- 카드 그리드: 썸네일, 제목, 한 줄 설명, `[구글 시트 사본 만들기]` 버튼(외부 링크 아이콘 표시)

**D. 갤러리 탭**
- "선생님들의 작품" 카드 그리드: 작성자(학교/이름 선택적 비공개 가능), 스크린샷, 짧은 후기 텍스트
- 빈 상태(empty state) placeholder: "아직 공유된 작품이 없어요. 첫 번째 주인공이 되어보세요!"

### 3.5 FAQ (`/faq/`)

- 검색창(상단) placeholder: "궁금한 점을 검색해보세요 (예: 권한 오류)"
- 카테고리 필터 칩: 전체 / 제미나이 관련 / 시트·앱스크립트 관련 / 계정·권한
- 아코디언 리스트(질문 클릭 시 펼쳐짐), 각 답변에 관련 페이지 링크 포함 가능

### 3.6 연수 소개 (`/about/`)

- 연수 목적, 대상, 진행 방식(자기주도 학습 안내) 텍스트 섹션
- 문의하기 폼 또는 이메일 링크
- (선택) 운영진/제작자 소개 카드

## 4. 컬러 / 타이포그래피 토큰 제안

> 원칙: 신뢰감(교육기관 톤) + 친근함(초등 대상) 동시 확보. 채도 높은 원색은 포인트로만 소량 사용하고, 배경은 밝고 여백이 넉넉한 톤 유지.

### 4.1 컬러 토큰

| 토큰 | 값(예시) | 용도 |
|---|---|---|
| `color-primary` | `#3D6BFF` (신뢰감 있는 블루) | 주요 버튼, 링크, 활성 메뉴 |
| `color-primary-hover` | `#2C54D9` | 버튼 hover |
| `color-secondary` | `#FFB020` (따뜻한 옐로/오렌지) | 보조 CTA, 배지, 하이라이트 |
| `color-accent` | `#2FBF71` (그린) | 성공/완료 상태, "쉬움" 난이도 배지 |
| `color-accent-warn` | `#FF6B6B` | 주의/에러 안내(권한 오류 등) |
| `color-bg` | `#FFFFFF` | 기본 배경 |
| `color-bg-soft` | `#F5F7FB` | 섹션 구분 배경(연한 회청색) |
| `color-bg-footer` | `#EDEFF5` | 푸터 배경 |
| `color-text-heading` | `#1F2430` | 제목 |
| `color-text-body` | `#4A4F5C` | 본문 |
| `color-text-muted` | `#8A8F9C` | 캡션, 보조 설명 |
| `color-border` | `#E2E5ED` | 카드 테두리, 구분선 |

- 난이도 배지 색상: 쉬움=`color-accent`(그린), 보통=`color-secondary`(옐로), 도전=`color-accent-warn`(레드) — 초등 교사에게 익숙한 신호등 색 체계 활용

### 4.2 타이포그래피

| 토큰 | 폰트 예시 | 크기(rem) | 용도 |
|---|---|---|---|
| `font-family-base` | Pretendard, Noto Sans KR, sans-serif | - | 본문 전체(한글 가독성 우선) |
| `font-display` | Pretendard (Bold) | - | 히어로/섹션 제목 |
| `text-h1` | Bold | 2.25rem (36px) | 페이지 최상단 제목 |
| `text-h2` | Bold | 1.75rem (28px) | 섹션 제목 |
| `text-h3` | SemiBold | 1.25rem (20px) | 카드 제목 |
| `text-body` | Regular | 1rem (16px) | 본문, 줄간격 1.6 |
| `text-caption` | Regular | 0.875rem (14px) | 캡션, 보조 텍스트 |
| `text-code` | Monospace (D2Coding, JetBrains Mono) | 0.9rem | 코드 블록 |

- 원칙: 초등 교사 대상이므로 본문 최소 16px 이상, 줄간격(line-height) 1.6~1.8로 넉넉하게. 제목은 굵고 명확하게, 장식적 폰트 지양.

## 5. 재사용 컴포넌트 목록

| 컴포넌트 | 설명 | 주요 사용처 |
|---|---|---|
| **Header / Footer** | §2에서 정의한 전역 내비게이션 | 전 페이지 |
| **Button (Primary/Secondary/Ghost)** | CTA용. Primary=채워진 블루, Secondary=아웃라인, Ghost=텍스트만 | 전 페이지 |
| **Card (기본형)** | 썸네일/아이콘 + 제목 + 설명 + 액션 버튼. 그림자 약하게, radius 넉넉히(12~16px) | 홈 가치제안, 템플릿, 레시피 |
| **Card (난이도 배지 포함)** | 기본 카드 + 상단 난이도/소요시간 배지 | 레시피 목록 |
| **Step Guide (스텝 안내 컴포넌트)** | 번호 원형 아이콘 + 제목 + 설명 + 스크린샷 영역, 세로로 연결선 표시 | 바이브 코딩 실습, 앱스크립트 실습 |
| **Code Block (코드/복사 컴포넌트)** | 모노스페이스 폰트, 우측 상단 "복사" 버튼, 언어 라벨(선택) | 앱스크립트 예제, 프롬프트 예시 |
| **Callout / Tip Box** | "선생님 TIP", "주의하세요" 등 배경색 있는 안내 박스 (아이콘+텍스트) | 실습 페이지 전반 |
| **Accordion (FAQ)** | 질문 클릭 시 펼침, 화살표 회전 애니메이션 | FAQ 페이지 |
| **Tabs** | 상단 탭 전환 (워크시트/템플릿/갤러리) | 실습/자료실 |
| **Progress Steps (진행 단계 표시)** | 가로 스텝 인디케이터(1/3, 2/3, 3/3) | 학습 트랙 하위 페이지 상단 |
| **Page Pagination (이전/다음)** | 하단 좌우 이동 버튼 | 학습 트랙 하위 페이지 하단 |
| **Empty State** | 콘텐츠 없을 때 안내 일러스트 + 문구 | 갤러리 빈 상태 |
| **Badge/Chip** | 난이도, 카테고리 필터용 작은 알약형 라벨 | 레시피, FAQ 필터 |
| **Breadcrumb** | 현재 위치 경로 표시 | 하위 페이지 상단 |

## 6. 반응형 / 접근성 원칙

### 6.1 반응형

- **브레이크포인트**: 모바일 `<768px` / 태블릿 `768~1024px` / 데스크톱 `>1024px`
- 홈/자료실의 카드 그리드: 데스크톱 3~4열 → 태블릿 2열 → 모바일 1열
- 헤더 메뉴: 데스크톱 가로 노출 → 모바일 햄버거 드로어
- Step Guide, 코드 블록은 모바일에서도 가로 스크롤 없이 전체 폭 사용(코드 블록만 내부 스크롤 허용)
- 이미지/스크린샷 placeholder는 `max-width: 100%` 고정, 비율 유지

### 6.2 접근성

- 텍스트 대비: 본문 텍스트 대 배경 명도 대비 **WCAG AA(4.5:1) 이상** 확보 (특히 `color-text-muted` 사용 시 확인)
- 모든 버튼/링크는 키보드 포커스 시 명확한 outline 표시
- 터치 타깃 최소 44x44px (교사 연령대 고려, 작은 버튼 지양)
- 아이콘만 있는 버튼(예: 복사 버튼)에는 `aria-label` 필수
- 스크린샷/일러스트에는 대체 텍스트(alt) 제공 — 특히 Step Guide의 스크린샷은 alt에 조작 내용 요약 포함
- 아코디언(FAQ), 탭(Tabs)은 `aria-expanded`, `role="tablist"` 등 표준 ARIA 패턴 준수
- 폰트 크기 확대(브라우저 200% 줌)해도 레이아웃 깨지지 않도록 상대단위(rem) 사용
- 색상만으로 정보 전달 금지 — 난이도 배지는 색+텍스트(예: "쉬움") 병기, 에러 안내도 색+아이콘+텍스트 병기

## 다음 작업자를 위한 메모

- 이 문서는 정보구조·카피 톤·컴포넌트 스펙까지만 다룬다. 실제 마크업/스타일 코드, 폰트 라이선스 확정, 정확한 색상 대비 검증(툴로 재확인 필요)은 구현 단계에서 진행할 것.
- 화면별 텍스트는 모두 placeholder이며 최종 카피는 연수 기획자 검수 필요.
- 컴포넌트는 §5 목록을 기준으로 최소 세트만 구현하고, 목록에 없는 컴포넌트는 임의로 추가하지 말 것(YAGNI).
